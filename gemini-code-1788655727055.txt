Actúa como un Arquitecto de Software Senior, Desarrollador Full-Stack y Diseñador UX/UI. Necesito que generes el proyecto completo, optimizado y liviano para la aplicación web interna "bissú Capacity".

### 1. OBJETIVO DEL PROYECTO
Crear una aplicación web de gestión de asistencia y capacidad de personal ("Capacity") para las tiendas de la marca "bissú ACCESORIOS".
El problema a resolver es aislar la edición por tienda: cada tienda solo debe ver y editar el registro de asistencia de sus propios empleados para el mes seleccionado, evitando que alteren datos de otras sedes o rompan la estructura de datos.

### 2. STACK TECNOLÓGICO (ULTRA LIGERO Y OPTIMIZADO)
- Backend: Node.js con Fastify (framework ligero, de alto rendimiento y bajo consumo de RAM).
- Base de Datos: PostgreSQL (usando cliente nativo 'pg' o 'postgres').
- Frontend: HTML5 + Tailwind CSS + Alpine.js / Vanilla JS (sin frameworks pesados estilo React/Angular).
- Autenticación: JWT (JSON Web Tokens) con contraseñas encriptadas con bcrypt/argon2.
- Despliegue/Nube: Preparado para consumir el mínimo recurso posible en el servidor.

### 4. MODELO DE DATOS (POSTGRESQL)
Genera el script SQL de migración/inicialización con las siguientes tablas relacionales:

1. `tiendas`
   - id_tienda (SERIAL PRIMARY KEY)
   - codigo_almacen (VARCHAR(20), ej. 'ALMA31')
   - nombre_tienda (VARCHAR(100), ej. 'JESUS MARIA')
   - correo_tienda (VARCHAR(150) UNIQUE NOT NULL, ej. 'bissujesusmaria@bissu.pe')
   - encargada (VARCHAR(150))
   - correo_encargada (VARCHAR(150))

2. `usuarios`
   - id_usuario (SERIAL PRIMARY KEY)
   - email (VARCHAR(150) UNIQUE NOT NULL)
   - password_hash (VARCHAR(255) NOT NULL)
   - id_tienda (INT NULL, FOREIGN KEY -> tiendas.id_tienda)
   - rol (VARCHAR(20) CHECK (rol IN ('TIENDA', 'SUPERVISOR', 'RRHH', 'ADMIN')) DEFAULT 'TIENDA')

3. `empleados`
   - id_empleado (SERIAL PRIMARY KEY)
   - dni (VARCHAR(15) UNIQUE NOT NULL)
   - codigo_empleado (VARCHAR(20))
   - nombre_completo (VARCHAR(150) NOT NULL)
   - puesto (VARCHAR(100)) -- ej. 'ASESOR DE VENTAS', 'ENCARGADA DE TIENDA'
   - regimen (VARCHAR(10)) -- 'FT' o 'PT'
   - id_tienda (INT NOT NULL, FOREIGN KEY -> tiendas.id_tienda)
   - situacion (VARCHAR(20) DEFAULT 'ACTIVO') -- 'ACTIVO', 'INACTIVO'

4. `capacity_diario`
   - id_registro (SERIAL PRIMARY KEY)
   - id_empleado (INT NOT NULL, FOREIGN KEY -> empleados.id_empleado)
   - fecha (DATE NOT NULL)
   - valor (NUMERIC(3,2) NOT NULL DEFAULT 0.0) -- Valores: 1.0, 0.5, 0.0
   - usuario_modificacion (INT, FOREIGN KEY -> usuarios.id_usuario)
   - fecha_actualizacion (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
   - UNIQUE(id_empleado, fecha)

Incluye un script de Seed Data inicial con datos de ejemplo (tienda JESUS MARIA, usuarios con correo @bissu.pe, empleados y asistencias de prueba para Agosto 2026).

### 5. REQUERIMIENTOS Y RUTAS DE BACKEND (FASTIFY)
Configura un servidor Fastify estructurado modularmente (`/src/routes`, `/src/controllers`, `/src/middleware`):

1. POST `/api/auth/login`
   - Recibe email y password.
   - Valida credenciales.
   - Retorna un JWT conteniendo: `id_usuario`, `email`, `rol`, `id_tienda`.

2. GET `/api/capacity?mes=2026-08`
   - Requiere autenticación JWT.
   - SEGURIDAD A NIVEL DE FILA (RLS): Si el rol es 'TIENDA', filtra los empleados/asistencias OBLIGATORIAMENTE por su `id_tienda`. Si es 'ADMIN' o 'SUPERVISOR', permite filtrar por query param de tienda opcional.
   - Devuelve la lista de empleados de la tienda con la matriz de fechas del mes seleccionado y sus valores diarios.

3. PUT `/api/capacity/bulk-update`
   - Requiere autenticación JWT.
   - Recibe un array de cambios: `[{ id_empleado, fecha, valor }]`.
   - Valida estrictamente en el backend que el usuario solo pueda modificar empleados pertenecientes a su `id_tienda`.
   - Actualiza o inserta (`UPSERT`) en la tabla `capacity_diario`.

4. GET `/api/capacity/export?mes=2026-08` (Para Power Query / BI)
   - Endpoint protegido por API Key o Bearer Token.
   - Devuelve la data desdinamizada y limpia en formato JSON estructurado listo para ser consumido directamente por Power Query sin necesidad de Unpivot manual.
